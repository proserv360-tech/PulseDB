### Monitoring performance
`c86925d` — **measure query latency, not TLS handshakes.**

`/api/connections/health` built a fresh `Pool` on every poll, so the reported
1497 ms was TCP + TLS + SCRAM against a pooler in `ap-northeast-1` rather than
anything the database did. Changed to use the warm pool and probe concurrently
instead of sequentially; raised the admin pool idle timeout from 10 s and
enabled `keepAlive`. Expected reading dropped to roughly 130–250 ms.

Residual constraint: the database is in Tokyo and the operator is in India — a
~130 ms round trip that no pooling change can beat.

## 29 July — alerting rebuilt around incidents

### Slack alert format
`d2e36fa` — 25 files, +4,515. The single largest commit of the month.

Replaced one-line alert messages with a structured format used by **all ten
alert rules**, not just bloat:

- Findings table, one row per affected object
- Suggested fixes keyed to incident number
- Runnable, quoted SQL in its own block
- Rendered as Block Kit code blocks so columns align in Slack

Supporting work: `pgmonitoringtool.incidents` created (migrations `0031`,
`0032`) — a table `statusPageService` had read and written for months without
it ever existing. One incident per affected object, with priority mapped from
per-rule thresholds, owner resolved from ownership rules, SLA target, fix
status and an append-only audit trail.

Two decisions worth recording:

- **Priority and severity are separate scales.** `priority`
  (critical/high/medium/low) is human triage and drives the SLA; `severity`
  (info/warning/critical) is machine routing that `min_severity` and the
  notifiers already speak. Changing the latter would have silently re-routed
  every configured destination.
- **The alert dedup key was about to break.** It keyed on message text, and
  structured messages embed live figures, so the 5-minute window would have
  suppressed nothing. Now keys on rule ID.

### Incidents UI

### Frontend data bugs
`5305a5c` — alert rules never displayed. `/api/alerts/rules` returns a bare

`54e2ab0` — invisible buttons and a page crash. Two causes:

- Editing a rule passed the raw database row into a form that then called
  `.includes()` on a field the row does not have, taking the section down.

## 30 July — rendering and speed

`6144a60` — data rendering. A codebase-wide sweep found **416 of 638 buttons**
and **177 form controls** with no background of their own, all rendering as
browser defaults against a dark UI. Fixed with a reset in `index.css` rather
than component by component; inline styles still win, so anything deliberately
styled is untouched.

`1ca1a38` — slowness. `enforcePasswordChange` ran an uncached
`SELECT must_change_password` on **every authenticated request** — one
control-plane round trip per API call, before the handler did any work.
Against a remote admin database with a 5-connection pool (1 on Vercel), a
screen firing ten requests paid over a second in latency for a boolean that is
false for every normal user. Now cached for 30 s and busted where the flag
changes.

Also fixed: the wait-event sampler queried `pgmonitoringtool.connections`,
which has never existed — the table is `fathom_connections`. Its catch treated
"relation does not exist" as "no connections", so it ran against nothing while
paying a failed round trip **once per second**.

## Themes

**One bug class dominates.** A query fails, a `catch` returns `[]` or a 500,
and the feature looks unused rather than broken. It accounts for the audit
export, the incidents table, the alert rules screen, the wait-event sampler and
four more missing tables. The fix each time was the same: make the failure
visible.

**A second class is shape mismatch.** An endpoint returns a bare array, the
component reads `data.something`, gets `undefined`, and silently keeps its
fallback. Found in the alerts list, the rules list, the OTel chart and
`ReliabilityTab`.

**Measurement lied twice.** The 1497 ms health reading was almost entirely
connection setup. The wait-event sampler reported healthy while querying a
table that did not exist.
